# 走れだいごくん — 設計ドキュメント

成蹊大学の学園祭でURL/QRを配布し、スマホのブラウザで遊んでもらう2Dドット絵ゲーム。
教授（だいごくん）がキャンパスを走り回り、60秒以内にアイテムを集めてスコアを競う。

このドキュメントは実装・レビューの共通の拠り所。ここに書かれた決定を変えたいときは、
コードを変える前にこのファイルを更新して理由を書く。

---

## 1. ゲームルール（確定）

| 項目 | 決定 |
|---|---|
| 終了条件 | スコア制。**60秒**の時間切れで終了 |
| アイテム | 3種。**レポート用紙 1点（約30個）／教科書 3点（約10個）／研究費の封筒 10点（約3個）**。名前・個数は定数で後から変更可 |
| 配置 | 候補地点（`spawnPoints`）をマップデータに固定し、ゲーム開始時にその中からランダムに選ぶ。壁の中に出ない保証はデータ側で持つ |
| 邪魔要素 | なし。障害物は建物・植え込み・敷地外の壁のみ |
| 移動 | 8方向、速度は一定（ダッシュなし）。斜め移動は正規化して速度が増えないようにする |
| アニメ | 歩行アニメは **4方向分（下・上・左・右）**。斜め移動時は横成分優先で左右のアニメを使う。右向きは左向きの反転で可 |
| 取得判定 | 教授のボディと重なったら取得。取得時に効果音＋スコア加算＋小さな「+3」等のポップ表示 |
| 残り10秒 | タイマー表示を赤くして拡大、警告音を1回鳴らす |

## 2. 画面の流れ（確定）

```
Title ──tap──▶ HowTo ──tap──▶ Play ──60秒──▶ Result ──「もう一度」──▶ Play
                                                        └─「タイトルへ」──▶ Title
```

| シーン | 内容 |
|---|---|
| `BootScene` | テクスチャ・音の準備。**プレースホルダーのテクスチャはここで `Graphics` から生成**する（本番スプライトが来たら PNG 読み込みに差し替える） |
| `TitleScene` | タイトルロゴ、教授（腕組みポーズ）、「タップしてスタート」の点滅。**最初のタップで `AudioContext` を resume**（iOS Safari 対策）。端末ハイスコアがあれば表示 |
| `HowToScene` | 1画面で説明：「指でなぞって走る」「60秒でアイテムを集めろ」「アイテムの点数表（3種のアイコン＋点数）」。タップで開始 |
| `PlayScene` | メインゲーム。カメラが教授を追従。HUD は別の `HudScene` を `launch` して UI カメラをマップから分離する |
| `HudScene` | 残り時間（上部中央・大きく）、スコア（上部右）。残り10秒で強調 |
| `ResultScene` | スコア、取ったアイテムの内訳（種類ごとの個数）、端末ハイスコア更新なら「NEW RECORD」、「もう一度」「タイトルへ」。`submitScore()` フックを呼ぶ（今は no-op） |

## 3. 見た目・解像度（確定）

| 項目 | 決定 |
|---|---|
| 内部解像度 | **240×400**（縦持ち）。`Scale.FIT` + `autoCenter: CENTER_BOTH`。`pixelArt: true`、`roundPixels: true` |
| タイル | **16px**。マップは **60×80タイル = 960×1280px** |
| 教授 | **16×24px**（当たり判定は足元 12×10 程度、原点は足元中央） |
| 建物 | 1棟 4〜8タイル四方（64〜128px）の1枚スプライト。足元の矩形（footprint）を衝突判定に使う。見た目は上に伸びてもよい（屋根がfootprintより上にはみ出す） |
| 教授の見た目 | 短い黒髪、紺のスーツ、白シャツ、**えんじ色のネクタイ**。タイトル用に腕組みポーズ1枚 |
| 配色 | 背景の地面は明るい緑（芝）と薄いベージュ（通路）。本館は赤レンガ＋白帯。情報図書館はガラス（水色）＋白い球体。10号館は高層のグレー。学生会館は青い半円アーチ窓。トラスコンガーデンは三角トラス屋根 |
| 速度 | 教授 **96px/s（6タイル/s）**。定数 `PLAYER_SPEED` |

> 画面比率について：240×400（3:5）は多くのスマホ（9:19.5）より横長なので、FIT だと上下に黒帯が出る。
> まずはこれで実装し、実機で見てから `Scale.RESIZE` で高さを可変にするか判断する。

## 4. 操作（確定）

- **フローティング・バーチャルスティック**：画面のどこを触ってもそこが中心。指の移動量（最大半径 40px 程度）で方向と「倒し具合」を決める。倒し具合は無視して常に最高速でもよい（60秒ゲームなので）。デッドゾーン 8px
- スティックは半透明の円（外枠＋内側ノブ）として描画。指を離すと消える
- HUD とは別レイヤー（`HudScene` 内で描画してよい）
- マルチタッチ：最初の指だけを採用。2本目は無視
- **PC用**：矢印キー / WASD。PC で動作確認するため必須
- `pointerdown` 時に `AudioContext` の resume を試みる（Title だけでなく毎シーンで安全に呼べる関数にする）

### 5.4 スポーン候補
- **レポート用紙（1点）**：通路上に 60 箇所程度の候補 → 毎回 30 個
- **教科書（3点）**：各建物の入口付近（footprint の南辺のすぐ外）に 21 箇所 → 毎回 10 個
- **研究費の封筒（10点）**：遠い場所 8 箇所（けやきグラウンドの奥、13 西一号館の裏、20 史料館の裏、10号館の北、体育館の裏 など）→ 毎回 3 個
- 候補はすべて通行可能タイルの中心に置く。起動時に「候補が衝突矩形と重なっていないか」をデバッグチェックして `console.warn` する

## 6. 音（確定）
- **効果音のみ、BGMなし**。音声ファイルは使わず **WebAudio で合成**する（`src/audio/sfx.ts`）：
  - 取得音：短い上昇音（点数が高いほど高い音／長い）
  - 残り10秒：警告音1回
  - 終了：下降音
- `AudioContext` はユーザー操作（pointerdown）で生成・resume。失敗しても例外を外に出さない

## 7. スコア保存とランキングの差し込み口（確定）
- `src/score/storage.ts`：`localStorage` に端末ハイスコア（key: `hdk:highscore:v1`）。読み書きは try/catch
- `src/score/submit.ts`：`submitScore(result: GameResult): Promise<void>` を export。**今は何もしない**（コメントで「後で Workers + D1 に POST」と明記）。`ResultScene` から呼ぶ

## 8. 素材の方針
- **Phase 1**：`BootScene` で `Graphics` → `generateTexture` によるプレースホルダー。建物は色付き矩形に番号文字、教授は 16×24 の矩形に色分け、アイテムは 8×8 の色違い
- **Phase 2**：`npm run gen:assets`（`scripts/gen-assets.mjs`、Node 20、追加依存なし）で本番ドット絵を生成し `public/sprites/` に PNG として配置。`BootScene` の読み込みを差し替えるだけで済むよう、**テクスチャキーを定数化**して `src/assets/keys.ts` にまとめる
- スプライトシート規約（Phase 2 で使う）：教授 `professor.png` 16×24 × 4方向 × 歩行3フレーム（計12フレーム）＋腕組み1枚 `professor_idle_title.png`（32×48）。横一列192×24、方向順は `down, left, right, up`、各方向は立ち姿→歩行2枚。足元中央を原点とする
- アイテムは各8×8、欅・桜は各16×20、植え込みは16×16。全画像は透過RGBA 8bit PNG（非インターレース）
- 建物は `FACILITIES` の `solid:true` 全21棟（体育館を含む）。幅 `rect.w*16`、高さ `rect.h*16+roofExtra`、原点はfootprint下辺中央。アトリオは地面なのでPNGを作らない
- 配信URLは `/sprites/<テクスチャキー>.png`。Viteの`dist/assets/`と区別する。`BootScene.preload()`で読み込み、`loaderror`のキーだけ従来のGraphics描画で補う。`create()`冒頭で予定キーのテクスチャ有無（教授はフレーム0〜11）も確認し、デコード失敗などで欠落したテクスチャも補完する

## 11. 完了の定義（Phase 1）
- `npm run typecheck`（`tsc --noEmit`）と `npm run build` が通る
- PC の Chrome で：タイトル→遊び方→プレイ→リザルト→もう一度、が一周する。矢印キーで8方向に動き、建物にぶつかって止まり、アイテムを取るとスコアが増え、60秒で終わる

- `npx wrangler deploy --dry-run` が通る
- 対象ブラウザ：**iOS 16 以降の Safari、Android Chrome 110 以降**（ビルドターゲット ES2022 の根拠）

## 12. 設計レビュー反映（Codex レビュー 2026-11-08）

以下は Codex の設計レビューで指摘され、採用した決定。§1〜§10 と矛盾する場合は**こちらが優先**。

### 12.1 表示領域・スケール（§3 の補足）
- 外側の `#shell` が safe-area を受け持つ：`height: 100dvh`（フォールバック `100vh`）、`box-sizing: border-box`、四辺に `padding: env(safe-area-inset-*)`。Phaser の親要素はその中の **padding なしの `#game`**（`width: 100%; height: 100%`）。ScaleManager は親を padding 込みで測るため、親に padding を付けると canvas がはみ出す
- **内部解像度は幅 240 固定、高さは起動時に親要素の縦横比から計算し 400〜520 にクランプ**する（`height = clamp(round(240 * parentH / parentW), 400, 520)`）。黒帯を最小化するため。シーンは `400` を直書きせず **`this.scale.height` / `this.scale.width`** でレイアウトする。HUD は上辺基準、「タップしてスタート」等の下部要素は下辺基準
- `Scale.FIT` + `autoCenter: CENTER_BOTH` は維持。余った黒帯（canvas 外）はタッチ対象外でよい。`body` の背景は `#1b1b2f`
- `scale.on('resize')` で：スティック解除、canvas 境界の更新。横向きになったら「縦にしてね」のオーバーレイを HUD に出す（ゲームは止めなくてよい）
- カメラ追従は **`startFollow(player, true)`**（第2引数 roundPixels。省略すると false に上書きされる）

### 12.2 音の解禁（§6 の補足）
- `AudioContext` は `src/audio/sfx.ts` が**単一所有**。`unlockAudio()` は何度呼んでも安全（冪等）
- WebKit では touch の `pointerdown` がユーザーアクティベーションにならないため、**`pointerdown` と `pointerup` の両方**で `unlockAudio()` を呼ぶ（Phaser の `input.on('pointerdown'|'pointerup')` を全シーン共通のヘルパで登録）。`state === 'running'` になるまで毎回 resume を試す。Promise の reject は握りつぶして次回再試行
- `document.visibilitychange` で visible に戻ったときも resume を試す

### 12.3 スティック入力の所有者（§4 の補足）
- **スティックは `PlayScene` が所有**する（`VirtualStick` を PlayScene 内に作り、描画は `setScrollFactor(0)` + 高い `depth`）。`HudScene` は表示専用で、interactive なオブジェクトを置かない
- 採用した Pointer の **`pointer.id` を保持**し、その指の `pointermove` だけで方向を更新、その指の `pointerup` / `pointerupoutside` で解除。2本目以降の指は無視し、先の指を離しても押下中の2本目へ自動移譲しない（次の新しい押下から採用）
- 次のタイミングで**ベクトルと速度をゼロにして解除**：`pointerupoutside`、`game.events.on('blur')`、`visibilitychange` で hidden、`scale.on('resize')`、シーンの `shutdown`
- 半径 40px・デッドゾーン 8px は**内部座標（ゲーム座標）単位**

### 12.4 時計と終了処理（§1・§2 の補足）
- 残り時間は **Phaser の `delta` 積算**で減らす（`update(time, delta)`）。タブが非表示の間は Phaser が止まるのでゲームも止まる（復帰後に続きから）。実時間ではなく「遊んでいた時間」で60秒
- 終了処理 `finish()` は**一度だけ実行**（`ended` フラグ）。順序：①`ended = true` ②入力解除・速度ゼロ・`physics.pause()` ③以後の取得コールバックは `ended` を見て無視 ④結果スナップショット（スコア・内訳） ⑤`scene.stop(HUD)` ⑥`scene.start(Result, snapshot)`
- 取得判定と時間切れが同一フレームで起きた場合、**`update` の先頭で残り時間を評価して `finish()` を先に呼ぶ**（締切が優先）
- 残り10秒の警告は `warned` フラグで一度だけ

### 12.5 再プレイ時の初期化（§2 の補足）
- Scene インスタンスは再利用されるので、**プレイ状態はクラスフィールドの初期化子ではなく `init()` / `create()` で毎回代入**する（スコア、内訳、残り時間、`warned`、`ended`、スティック、アイテム配置）
- `shutdown` イベントで：`game.events` / `scale` / `document` に登録したリスナーの解除、タイマー・Tween の破棄、スティックの破棄、HUD の `stop`

### 12.6 スポーン（§5.4 の補足）
- 各種類の抽選は**重複なし**（同じ候補を2回選ばない）。種類をまたいで同じタイルを使わないよう、候補タイルは全種類で**一意**にする（データ側で保証、起動チェックで検出）
- 候補が必要数より少ない場合は、ある分だけ出して `console.warn`
- アトリオ（19）は建物ではないので教科書候補は置かない。教科書候補は「建物20棟＋体育館」の南辺の外側に1つずつ（南辺が通路に面していない建物は、面している辺に置く）
- 起動時デバッグチェック：①候補が衝突矩形と重ならない ②候補が一意 ③**開始地点からの BFS で全候補に到達可能** ④到達不能な通行可タイルが 0 であること。いずれも失敗は `console.warn`（ゲームは止めない）

### 12.7 衝突体（§3・§5.1 の補足）
- **衝突矩形はマップデータが正**。建物の見た目スプライトとは別に、footprint から**不可視の Static body**（`physics.add.staticGroup` に矩形）を作る。スプライト自体にボディを付けない（画像寸法でボディが上書きされる事故を防ぐ）
- 教授のボディ：`setSize(12, 10)` + `setOffset(2, 14)`（16×24 の足元）
- `Graphics.generateTexture()` は Graphics 自身の描画しか焼き込まない。建物番号の文字は **別の `Text` を重ねる**。`generateTexture(key, width, height)` のサイズを必ず明示する

### 12.8 スコア保存（§7 の補足）
- 読み出した値は「有限の非負整数」として検証し、不正なら 0 扱い
- 書き込み失敗時もゲームは継続。セッション中はメモリ上の最高記録を持ち、NEW RECORD 判定はそれと比較する

### 12.9 表示・フォント
- Text のフォントは `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", sans-serif`、最小サイズは内部座標で 10px。HUD の Text は**値が変わったときだけ** `setText`
- 日本語の説明文（HowTo・Result）は実機で欠けがないことを確認する

### 12.10 配信設定（§9 の補足）
- QR の配布先は **`workers.dev` のドメイン直下**（`base: "/"` のまま）
- SPA フォールバックは不要なので `wrangler.jsonc` から `not_found_handling` を外す（存在しないパスは 404 でよい）
- キャッシュは当面 Workers Static Assets の既定（`max-age=0, must-revalidate` + ETag）に任せる。将来 immutable にするならハッシュ付きファイル名のものに限定し、HTML と固定名 PNG には適用しない

## 13. 実装メモ（Phase 1）

実装時に §1〜§12 から細部を変えた点・補った点。

- **時計の評価タイミング**：§12.4 の「`update` の先頭で残り時間を評価」は、Arcade Physics の取得判定（overlap）が Scene の `UPDATE` イベントで `scene.update()` より**前**に走るため、そのままでは締切が優先されない。時計は `PRE_UPDATE` イベント（物理より前）で進め、締切なら `finish()` する
- **音の解禁リスナー**：§12.2 の「Phaser の `input.on` で全シーン共通のヘルパで登録」の代わりに、`sfx.installAudioUnlock()` が `window` の capture 段で `pointerdown` / `pointerup` / `touchend` / `keydown` を受けて `unlockAudio()` を呼ぶ。シーンごとの登録漏れが起きず、DOM のユーザー操作ハンドラ内で確実に呼ばれるため
- **終了演出**：`finish()` の ④（スナップショット）と ⑤（HUD stop）の間に 0.9 秒「タイムアップ！」を表示する。この間は物理停止・入力解除済みで、取得は `ended` で無視される
- **マップの補い**：§5.1 の「入れない」中高エリアを `school_area`（x=1..12, y=19..61）として木立の壁で塗りつぶした。欅並木・参道の木は1タイルおき（横断できるように）、構内道路を塞がないよう y=60 までにした。正門の左右 (49,66)(52,66) は門柱（壁）
- **教授のスプライトシート**：並びは `down, left, right, up` × 3フレーム（`src/assets/keys.ts`）。プレースホルダーは右向きも個別に描いている（反転ではない）。Phase 2 の `professor.png` もこの並びにするか、変えるなら `keys.ts` を合わせる
- **横向き案内**：「縦にしてね」はタッチ端末で横向きのときだけ HUD に出す（PC の横長ウィンドウでは出さない）。横向きで起動した場合、内部解像度の高さは 400
- **共通 UI ヘルパー**：`src/scenes/ui.ts`（文字スタイル・ボタン・registry キー）を §10 の構成に追加
- **時計の delta**：時計は物理と同じ delta を上限なしで積算する（上限を付けると低速端末で時計だけ遅れる。極端な delta は Phaser の TimeStep が平滑化する）
- **スティック解除時の停止**：`VirtualStick` は解除（`pointerup(outside)` / blur / hidden / resize）のたびに `onRelease` を同期的に呼び、PlayScene はそこで `player.halt()` する。物理が次の `update()` より先に走るため、ベクトルのゼロ化だけでは旧速度で1フレーム動く。シーン破棄時は呼ばない
- **斜めのアニメ向き**：§1 の「斜めは横成分優先」は、正規化後の横成分の絶対値が `ANIM_HORIZONTAL_THRESHOLD`（0.25、`config.ts`）以上なら左右、未満なら上下とする。上下に倒したときの微小な横ぶれで横向きにならないための閾値
